## 第一章：代理客户端两大底层工作模式解密

科学上网客户端在接管操作系统流量时，主要有两种完全不同的技术路径：

```
【模式 1：系统代理 (System Proxy / HTTP / SOCKS5)】
用户应用 (Chrome / Edge) ──► 设置系统 PAC/端口 (127.0.0.1:7897) ──► 代理客户端 ──► 境外节点
  └─ 局限：仅能接管遵循系统代理的主动 HTTP/HTTPS 请求；CMD 终端、UWP 应用、游戏 UDP 流量默认绕过不走代理。

【模式 2：虚拟网卡 (TUN / TAP 模式 - 终极接管)】
用户终端所有进程 (浏览器 / 终端 / 游戏 / Git) 
      │
      ▼ (OS 内核网络层全面捕获)
[ 虚拟 TUN 网卡 (如 mihomo-tun) ] ──► 驱动级规则分流引擎 ──► 目标网络
  └─ 优势：真正的“全局无死角劫持”，终端 git push、Docker、游戏全自动分流，体验与真实物理网卡无异。
```

### 1.1 系统代理的致命死角
系统代理仅是在操作系统注册表写入了 `127.0.0.1:7897` 类似的本地监听端口。对于绝大多数命令行工具（如 `curl`、`npm`、`git`）、或者走非标准 TCP/UDP 协议的外服网络游戏，系统代理完全处于“失灵”状态，依然直连国内公网导致超时。

### 1.2 为什么必须开启 TUN 虚拟网卡模式？
现代代理工具（如 **Clash Verge Rev** 或 **Sing-box**）内置的 **TUN 模式**，是在操作系统内核直接创建一块虚拟网卡，通过篡改默认路由表将整机的所有流量（包括 ICMP Ping 包与游戏 UDP 数据报）全部引流至分流引擎。
> **调优准则**：追求极致省心与全功能接管的用户，强烈建议在客户端设置中安装并开启 **TUN 模式**。详见实战教程：[《Clash Verge Rev 2026 新手到进阶配置教程》](/clients/clash-verge-rev-tutorial)。

## 第二章：DNS 污染阻断机制与 Fake-IP 最佳实践

### 2.1 什么是 GFW 的 DNS 污染？
当你在浏览器输入 `google.com` 时，本地计算机会向运营商 DNS 发起查询。GFW 的嗅探探针会在真正的海外 DNS 响应返回之前，**伪造一个错误的 IP 地址（如 127.0.0.1 或不可达 IP）**抢先应答你的计算机。你的浏览器拿到假 IP 去连接，自然直接报错中断。

### 2.2 Redir-Host vs Fake-IP 模式终极对比

为了彻底根除 DNS 污染并加速首屏渲染，现代代理内核引入了 **Fake-IP** 机制：

* **Redir-Host（传统模式）**：客户端先通过代理节点去向海外干净 DNS 查询域名的真实 IP，拿到真实 IP 后再建立连接。缺点是每次解析都要额外消耗一次跨洋往返时间（150ms+），导致网页首屏响应迟滞。
* **Fake-IP（推荐现代模式）**：客户端本地建立一个虚拟的专用 IP 池（通常为 `198.18.0.1/16`）。当浏览器发起请求时，客户端**瞬间（0毫秒）**返回一个假 IP 给浏览器；同时在内核内部将该假 IP 映射到请求的真实域名，直接将带域名的请求包抛给海外节点由落地机房代为解析。

| 对比维度 | Redir-Host 模式 | Fake-IP 模式 (推荐) |
| :--- | :--- | :--- |
| **首屏 DNS 解析时延** | 100ms ~ 300ms（需跨洋等待真实解析） | **0 ms**（本地虚假网段瞬时响应） |
| **抗 DNS 投毒污染能力**| 中等（依赖加密 DoH/DoT） | **100% 免疫**（本地完全不向公网发包） |
| **游戏与特殊应用兼容性**| 较好 | 极佳（现代内核均支持 Fake-IP Filter 白名单） |
| **首选应用客户端** | 老旧客户端 | [Clash Verge Rev](/clients/clash-verge-rev-tutorial)、[Shadowrocket](/clients/shadowrocket-ios-setup-guide) |

## 第五章：高频故障速查与排错决策链（Troubleshooting）

对照以下常见症状，30 秒快速定位并解决 90% 的科学上网客户端故障：

### 故障 1：开启代理后微信、百度打不开，网页提示“无法连接到互联网”
* **病因**：DNS 污染或路由死循环，客户端拦截了国内本地流量。
* **解决方法**：
  1. 检查客户端是否误切到了“全局模式（Global）”，务必将其修改回 **“规则分流模式（Rule）”**；
  2. 在设置中开启 **系统代理自动旁路（Bypass Domain/IP）**，确保局域网 IP（`192.168.x.x`、`10.x.x.x`）处于直连白名单中。

### 故障 2：访问 ChatGPT 提示“1020 报错”或“Access Denied”
* **病因**：节点 IP 为普通机房共享广播 IP，被 Cloudflare / OpenAI 列入高风险池。
* **解决方法**：
  1. 切换至带有 **“原生（Residential/Native）”** 标记的专用节点；
  2. 首推切换到 **[极连云](/reviews/jilian-cloud)** 或 **[光速云](/reviews/guangsu-cloud)** 的新加坡或美西专属 AI 节点，重开无痕窗口即可秒进。详阅：[《ChatGPT 与 Claude 防封锁实战》](/unlock/chatgpt-claude-ai-unlock-guide)。

### 故障 3：TUN 虚拟网卡安装报错或启动失败
* **病因**：Windows 系统缺少管理员运行权限，或第三方安全杀毒软件（如 360、火绒、电脑管家）拦截了网卡驱动注入。
* **解决方法**：
  1. 退出杀毒软件，右键点击客户端图标选择 **“以管理员身份运行”**；
  2. 在 Clash Verge Rev 的“内核设置”中点击“重新安装服务模式（Service Mode）”，安装成功后即可常驻开启 TUN。

## 客户端配置常见答疑 FAQ

### Q1：Clash Verge Rev 和老版本 Clash for Windows（CFW）有什么区别？
答：Clash for Windows 早在 2023 年底已彻底停止维护，存在未修补的安全漏洞且不支持 VLESS Reality 等现代协议。**Clash Verge Rev** 是目前开源社区公认的最主力继承者，基于 Rust + Tauri 开发，不仅内存占用极低，且默认采用性能强悍的 Mihomo（Clash.Meta）开源内核，完美支持最新的协议与规则集特性。

### Q2：使用代理客户端会消耗电脑很多电池电量吗？
答：系统代理模式本身几乎不增加功耗；开启 TUN 虚拟网卡模式后，由于所有网络数据包需要经过内核态与用户态的多次拷贝处理，CPU 负载会略微提升 1%~3%，在笔记本移动办公场景下耗电差异几乎难以察觉。但在手机端（如 iOS 小火箭），建议开启“按需连接（On-Demand）”，在连接 Wi-Fi 时自动唤醒以节省电量。

### Q3：为什么我在客户端里测试节点延迟显示正常（几百毫秒），点击后却连不上网页？
答：客户端内的“小黄灯/小绿灯测速”通常只是测试向目标落地服务器建立一次短暂 TCP 握手的时间，**并不代表真实的 HTTP 网页传输已经打通**。如果节点被海外流媒体或大模型平台封禁了 IP，或者机房出口配置了错误的 DNS，就会出现“握手延迟正常但网页打不开”的假死现象。此时建议切换至更纯净的专用节点测试。
